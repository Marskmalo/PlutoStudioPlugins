# Pluto 资产命名助手使用文档

## 工具用途

Pluto_AssetNamingHelper 用于检查指定内容目录中的 Unreal 资产名称是否符合 SOD 资产命名规范。它会列出问题、解释原因并给出可行的建议名称，适合策划、美术和程序在提交资产前进行自查。

扫描只读取 Asset Registry 中的资产信息，不会加载、保存或修改资产。只有用户在“重命名影响矩阵”中明确纳入项目、点击“执行重命名”并再次确认后，工具才会加载并重命名对应资产。

## 打开工具

- 在 Level Editor 顶部打开 Pluto 菜单。
- 选择“资产命名助手”。
- 也可以从“窗口”菜单打开同一面板。
- 面板中的“使用文档”按钮会打开当前文档；文档不会单独占用 Pluto 菜单项。

## 开始一次扫描

- 打开插件时不会自动查询资产，避免进入工具就对大型内容目录发起扫描。
- 在“扫描范围”中选择需要检查的内容目录，例如 /Game/SOD。
- 确认路径后点击“开始扫描”或“重新扫描”。
- 工具会递归检查该目录及其子目录中的资产。
- `/Game/Developers/<User>/` 属于个人实验目录，其中由系统用户名形成的中文路径不会产生告警；目录内的资产仍会正常检查名称、类型前缀和其他规则。
- 扫描完成后再使用状态、资产类型和搜索框缩小结果范围。

## 资产类型筛选器

资产类型筛选器使用 Unreal 对应资产类的默认 Slate 图标和类型颜色。按钮具有明确的亮起和熄灭状态，交互与内容浏览器的官方筛选器保持一致。

- 所有类型都熄灭：不限制资产类型，显示全部扫描结果。
- 点亮一个类型：只显示该资产类型。
- 点亮多个类型：显示任意一个已点亮类型，类型之间是“或”关系。
- 再次点击已点亮的类型可将其熄灭。
- 筛选只改变当前列表显示，不会重新扫描，也不会修改资产。

## 命名状态

### 符合

名称满足当前已实现的 SOD 命名规则，可以继续使用。

### 历史例外

名称不完全符合新规则，但属于规则中允许保留的历史资产或兼容情况。通常不需要立即处理，迁移时仍建议复核引用关系。

### 建议迁移

名称存在可以明确识别的问题，工具会给出问题说明和建议名称。请先检查建议是否准确，再查看重命名影响。

### 禁止自动修改

资产风险较高，或工具没有足够信息安全地产生修改方案。例如关卡、核心蓝图、Redirector、外部来源不明确的资产。此状态不是“无法使用”，而是要求人工判断。

## PCG 资产

命名助手已经登记 PCG Graph、PCG Graph Instance 和 PCG Data Asset：

- PCG Graph 使用 `PCG_SOD_<Name>`，例如 `PCG_SOD_ForestScatter`。
- PCG Graph Instance 使用 `PCGI_SOD_<Name>_<Variant>`。
- PCG Data Asset 使用 `PCGDA_SOD_<Name>`。
- PCG Blueprint Element 仍使用 Blueprint 前缀，例如 `BP_SOD_PCG_FilterSlopeElement`。
- 不使用 `PCGG_`，因为 `PCG_` 已是 Unreal 官方示例采用的 Graph 资产前缀。
- 建议名称会归一化已有的 `_SOD_` 结构，不会把错误前缀和项目标识反复嵌套到新名称中。

## 结果列表

- 资产名称：显示资产默认图标和当前名称；悬停可查看包路径。
- 类型与归属：显示 Unreal 资产类型以及规则判断出的资产归属。
- 状态：显示符合、历史例外、建议迁移或禁止自动修改。
- 问题：使用面向策划和美术的中文说明；悬停可查看更具体的技术诊断。
- 建议名称：仅在规则能够确定建议时显示，不确定时显示横线。
- 操作：可在内容浏览器中定位资产，或进入重命名影响矩阵。

## 搜索与状态筛选

搜索框会匹配资产名称、路径、资产类型、问题说明和建议名称。状态卡片可独立开关，用于只查看某一类结果。状态筛选、类型筛选和文本搜索会同时生效。

如果列表意外为空，请依次检查：是否熄灭了需要的状态、是否点亮了不相关的资产类型、搜索框中是否仍有文字。

## 定位、预览与导出

- “定位”会在内容浏览器中选中对应资产，不修改资产。
- “重命名…”打开独立的“重命名影响矩阵”；仅打开矩阵不会修改资产。
- 矩阵可搜索、仅显示需人工确认项，并可逐项纳入或排除当前预览计划。
- 选择矩阵中的资产后，下方详情区会显示完整路径、问题、引用者与依赖列表。
- “导出报告”会把当前扫描结果输出为 CSV，便于评审、分工和留档。

## 重命名影响矩阵

在主结果表中选择一个或多个资产，然后点击“重命名…”即可打开矩阵。矩阵是可缩放的独立窗口，多项结果使用虚拟化列表显示，不会像普通消息框一样随着选择数量增加而无限变长。

- 每行“纳入”复选框决定点击“执行重命名”时是否处理该资产。
- 表头三态复选框统一控制当前筛选后可见且有建议名称的资产：空框表示全部排除，勾选表示全部纳入，横线表示只纳入一部分。
- 能够进入受控流程的资产默认纳入；需要人工确认的资产默认排除，但用户复核后可以手动纳入。
- 没有安全建议名称的资产不能纳入，也不会进入执行队列。
- 搜索框可匹配当前名称、建议名称、资产类型、路径和问题说明。
- “仅显示需人工确认”会隐藏能够进入受控流程的项目，便于集中复核风险项。
- 引用者和依赖列显示数量；选中某行后，下方详情区显示对应包路径列表。
- “在内容浏览器中定位”可以回到原资产继续检查。
- “可进入受控流程”表示命名建议相对明确，但仍然只有在用户确认后才会修改资产。
- “需人工确认”表示资产类型风险较高，或规则明确要求人工检查引用关系。
- “无安全建议”表示信息不足，不应猜测新名称。
- “执行重命名”会先检查批次内目标名称重复、目标名称已被占用和资产加载失败；任一检查失败时整批不会开始。
- 检查通过后会显示一次最终确认，其中明确列出执行数量和需人工确认的数量。
- 确认后通过 Unreal AssetTools 执行重命名并更新可解析引用，成功后主面板会自动重新扫描。

## 大批量导入建议

工具不会在打开面板时自动扫描，也不会在每次导入资产时同步阻塞命名，因此不会直接拖慢批量导入流程。建议先完成一批导入，再选择本批次目录执行一次扫描。

对规模很大的目录，应从较小的业务目录开始扫描，而不是直接选择 /Game。类型筛选和文本搜索只处理已经取得的结果，不会再次访问 Asset Registry。

## 重命名安全边界

扫描、筛选和打开影响矩阵本身不会修改资产；实际修改只发生在用户点击“执行重命名”并通过最终确认后。即使建议名称看起来正确，也应先确认引用者、依赖项、版本控制状态和团队协作情况。

- 工具通过 Unreal AssetTools 执行重命名，不直接操作磁盘文件。
- 执行成功不等于已经保存；请检查并保存受影响资产与包。
- 工具不会自动清理 Redirector，应在确认引用正常后按项目流程处理。
- 需要人工确认的项目默认不纳入执行队列。
- 没有建议名称、目标名称冲突或加载失败的项目不会执行。
- 执行后应检查输出日志、重新扫描结果和关键引用资产。

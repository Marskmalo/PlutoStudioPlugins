# Pluto Function Library 使用与维护

> 状态：能力试用中；各项验证范围见第 4 节
> 建立日期：2026-10-01
> 适用范围：Pluto_FunctionLibrary 的通用蓝图能力，不包含项目玩法编排

## 1. 插件定位

通过蓝图右键菜单搜索 `PF_` 使用。插件目录为 `Pluto_FunctionLibrary`，运行时模块仍为 `PlutoFunctionLibrary`。
现有 GameplayTag 节点负责容器增删、查询与变更检测；本次不改变这些接口。

新增选择节点放在 `Pluto Function Library > Selection`，与 `Gameplay Tag` 同属一个函数库根分类，不依赖角色、输入资产或项目专属 Tag。

## 2. PF_ResolveLatestActivatedPair

### 2.1 用来做什么

在 A、B 两个条件之间选择最近激活的一方，只输出两个主导 Bool。
“激活”指相邻两次调用之间从 False 变成 True，不是每次传入 True 都重新抢占。

| 当前情况 | 选择规则 |
| --- | --- |
| 都无效 | A 主导、B 主导都为 False |
| 仅一个有效 | 有效的一方主导 |
| 两个有效，只有一个刚激活 | 刚激活的一方主导 |
| 两个持续有效 | 保持上次主导，不来回切换 |
| 两个同次激活 | 使用高级引脚中的平局设置，默认优先 A |
| 主导方失效，另一方仍有效 | 另一方接管 |

### 2.2 怎样接线

1. 在使用节点的蓝图中创建 `PF Latest Activated Pair Snapshot` 类型的成员变量，保留默认值，连接 `Snapshot` 引脚。不要使用函数局部变量，也不要每次新建默认结构值。
2. 这个变量只是节点自动使用的记事本。不用填写内部内容，也不用另接 Set；接好以后正常使用无需再管它，不要每次执行前清空。
3. 将 A、B 当前有效状态接到两个 Bool 输入。每次条件变化都调用，包括失效；持续每帧调用也可以。
4. 使用 `A Dominant`、`B Dominant` 两个 Bool 输出组织后续逻辑。
5. 每组独立判断使用独立的 Snapshot 变量。需要重新开始时，将 Snapshot 设回默认结构值。

节点带执行引脚，在本次调用结束前自动更新 Snapshot；不是纯查询。
状态仅含“上次 A 有效、上次 B 有效、上次 A 主导”三个 Bool，不使用隐藏全局缓存或时间戳。
不修改传入的 A、B，不输出或修改 Tag，不执行选中项对应的行为。

`Snapshot` 沿用 GameplayTag 变更检测中 `LastContainerSnapshot` 的历史快照含义：调用时读取上一次记录，返回前更新为本次记录。这里是算法运行所需的可更新历史，不是只读的 Debug 快照。

`Prefer A On Simultaneous Activation` 默认折叠在高级引脚中：True 优先 A，False 优先 B。
它只处理同次新激活，不会在双方持续有效时改变主导权。
同一次采样内发生的多次变化无法还原先后；如果顺序重要，应在每次实际状态变化时调用并传入两方的完整状态。

### 2.3 操作示例

| 操作 | A 有效 | B 有效 | A 主导 | B 主导 |
| --- | --- | --- | --- | --- |
| 激活 A | True | False | True | False |
| 再激活 B | True | True | False | True |
| 持续保持 | True | True | False | True |
| 关闭 A | False | True | False | True |
| 重新激活 A | True | True | True | False |

交换 A、B 后规则完全对称。当前条件与主导结果含义不同，不能用主导输出覆盖实际条件。

### 2.4 接入检查

- 双方持续有效却总是落到默认平局方时，先检查 Snapshot 是否每次被局部默认值重建；改变平局设置不能修复历史丢失。
- 只把输出接到打印，说明节点正在旁路观察，不代表实际行为已经消费新结果。正式接管时检查下游是否仍独立裁决、是否把行为结果误当作原始条件历史。
- 验收包括上述序列及镜像、持续保持、主导方退出、双方失效、同次激活、重置与独立调用者隔离。除 C++ 测试外，蓝图测试需连接真实成员变量重复调用。

### 2.5 从 State 引脚升级

参数名与引脚名统一改为 `Snapshot`，类型显示名改为 `PF Latest Activated Pair Snapshot`。原生类型名 `FPlutoLatestActivatedPairState` 与字段布局保留，以兼容已有蓝图变量；调用方已有成员变量不必改名。

插件启动时注册限定到此函数的 `State → Snapshot` 参数重定向，供旧节点重建时保留连接；不做全局 State 改名。重新构建并加载后应检查旧节点的 Snapshot 连接和蓝图编译结果，异常时停止保存并排查，不直接删除变量或重建整条玩法链。

## 3. 实现与维护

### 3.1 PF_ScaleFloatByRatios（比例计算试用节点）

入口：`Pluto Function Library > Math`，搜索 `PF_ScaleFloatByRatios`。

1. `Base Value` 填基准值，例如 `1000`。
2. 从 `Ratios` 拉线创建 `Make Array`，填入 `0.25`、`0.75`、`0.9`。点 Make Array 的添加引脚即可增加比例数量。
3. 从 `Values` 拉线创建 `Get`，索引 `0`、`1`、`2` 分别得到 `250`、`750`、`900`；也可用 `For Each Loop` 遍历结果。

这不是“将总量分完”：各项都是基准值乘对应比例，比例不用凑成 1，不自动排序、截断或归一化。允许零、负数、大于 1 的比例和重复项；空比例数组返回空结果。输入采用双精度浮点数，以保持现有浮点计算精度；调用方应提供有限数值并避免乘法溢出，节点不修复 NaN 或无穷大。

这是纯计算节点，没有执行引脚、Snapshot 或状态写回，也不需要专门创建成员变量。纯节点可能被多次求值；只有确需复用或保存时，才由调用方保存结果。它不判断结果属于什么玩法阶段，也不代替调用方应用结果。本轮不替换已有项目节点或接线。

接口、实现与测试分别位于 `Public/PlutoMathFunctionLibrary.h`、`Private/PlutoMathFunctionLibrary.cpp`、`Private/Tests/PlutoMathFunctionLibraryTests.cpp`。

### 3.2 PF_AdvanceFloatClamped（按速率增减试用节点）

入口：`Pluto Function Library > Math`，搜索 `PF_AdvanceFloatClamped`。

纯计算：`Clamp(CurrentValue + RatePerSecond × DeltaSeconds, MinValue, MaxValue)`。
正速率增加，负速率减少；只返回新值，不修改输入、不自动计时，没有执行引脚或 Snapshot。

| 引脚 | 怎样填写 |
| --- | --- |
| Current Value | 变化前的当前数值 |
| Rate Per Second | 每秒变化量，例如 `-20` 表示每秒减少 20 |
| Delta Seconds | 本次经过的秒数；每帧调用时接 Tick 的 Delta Seconds |
| Min Value / Max Value | 结果上下限，默认 `0 / 1` |
| Return Value | 计算后的新数值；需要累计时，由调用方 Set 回原变量 |

例如体力从 `40` 开始，以 `-20/秒` 推进 `0.5秒`，范围 `0～100`，得到 `30`。
蓄力从 `0` 开始，以 `+0.5/秒` 推进，范围 `0～1`，累计两秒达到上限；蓝图自行决定何时推进、何时释放或重置。
返回值未写回时，重复输入同一个当前值只会重复得到同一个结果，并不会自动累加。

输入使用双精度且须为有限数值，Delta Seconds 须非负，Min Value 须不大于 Max Value，并避免计算溢出。节点不修复无效输入、不交换上下限。先推进再限制范围；即使速率或时间为零，也会把越界结果限制回范围。上下限相等时返回该边界。它是匀速变化，不是缓入缓出或弹簧插值。

本轮只提供节点看样，不接管宿主玩法、不改 Tag 判断和状态写回。接口、实现及测试沿用 Math 文件，不新增模块依赖。

### 3.4 PF_DecomposeVector2DWithDeadZone（二维分解与硬死区）

入口：`Pluto Function Library > Math`。纯计算，输入 `Vector2D`，不需要 Snapshot。

| 引脚 | 用途 |
| --- | --- |
| Input Vector | 同一单位的 X/Y 分量；三维数据先由调用方选择平面，不混入 Z |
| Dead Zone | 径向死区半径，和向量长度同单位；长度等于边界也归零，负数按 0 |
| Direction | 通过死区时为单位方向，否则为 `(0, 0)` |
| Magnitude | 通过死区时保留输入长度，否则为 0；允许大于 1 |

例如 `(0.3, 0.4)` 的长度为 `0.5`：死区 `0.1` 时输出方向 `(0.6, 0.8)`、强度 `0.5`；死区 `0.5` 时两项归零。`Direction × Magnitude` 可以重建过滤后的向量。

这与手柄的径向死区思路一致，但不是完整的手柄处理器：它不读取设备、不做轴向死区、不重新映射死区外的强度、不做灵敏度曲线或上限裁剪。若 Enhanced Input 已经应用死区，需由调用方判断是否还要再次过滤，避免重复处理改变手感。零死区只过滤零向量。

输入分量或死区为 NaN/无穷大，或长度超出双精度可表示范围时，两项输出为零。纯计算不自动保存结果，也不修改输入；可用于整理多个来源合成后的二维意图。

替换旧计算前核对维度：旧链若采用三维长度加二维方向，存在 Z 分量时不能直接用本节点冒充等价替换。当前只交付能力，未接管宿主玩法。

### 3.5 PF_CalculateDirectionalAttenuation（相对方向衰减）

入口：`Pluto Function Library > Math`。纯计算，返回 Float 倍率，不返回“是否向后”的 Bool，也不执行移动。

| 引脚 | 用途 |
| --- | --- |
| Direction | 待判断的三维方向；不必预先归一化，向量长度不影响结果 |
| Reference Direction | 同一坐标空间的正向基准，不自动读取角色朝向 |
| Attenuation Strength | 衰减强度，限制到 `0～1`，默认 `1`；0 不衰减 |
| Minimum Multiplier | 最低倍率，限制到 `0～1`，默认 `0` |
| Return Value | 同向、朝向一侧或垂直返回 1；背离时按反向点积线性衰减，并受最低倍率约束 |

将两个方向归一化后：`Clamp(1 - Max(0, -Dot) × Strength, MinimumMultiplier, 1)`。最低倍率与衰减强度先各自限制到 `0～1`。任一方向为零或任一输入非有限时返回 1，表示不衰减。

参考方向可以是角色前方、流动方向、朝目标的方向等。只有参考方向确实传了角色前方，才可以把“背离”理解为角色相对向后；节点不以 Actor、镜头或世界 X 轴暗定前后。需要平面判断时，应在蓝图中先把两个方向的 Z 设为 0；节点本身使用全部三个分量。

强度 `0.6`、最低倍率 `0.3` 时，同向和垂直返回 `1`，完全背离返回 `0.4`。调用方再将倍率乘到速度、输入强度或其他数值上。它整体缩小强度，不改变方向，不单独削弱向量的反向分量，也不附带牵引。

启用条件、距离影响、参考方向来源、最终应用和其他效果的叠加由蓝图决定。两个向量节点沿用 Math 接口与实现；测试位于 `Private/Tests/PlutoVectorMathTests.cpp`，未增加项目依赖。
